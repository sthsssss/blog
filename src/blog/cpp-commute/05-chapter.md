앞의 객체·포인터·참조 초기화는 함수 호출에도 적용됩니다. 함수가 원본의 사본을 계산할 것인지, 원본에 직접 접근할 것인지는 매개변수 타입으로 표현합니다. “값으로 전달한다”는 말을 읽을 때도 어떤 타입의 값을 전달하는지 먼저 확인해야 합니다.

```cpp
int change_copy(Gradient value) {
    value.start = 100;
    return value.start;
}
```

`Gradient data{0, 255}; change_copy(data);`를 실행하면 매개변수 `value`를 원본으로 복사 초기화합니다. 함수는 별도 객체의 필드만 바꾸므로 반환값은 100이지만 호출자의 `data.start`는 0입니다. 지금처럼 기존 객체 이름을 인수로 제공한 경우의 복사입니다. 값 매개변수가 언제나 복사로만 만들어지는지는 10편과 11편에서 조건을 추가합니다.

**참조와 포인터는 기존 원본에 접근합니다.**

```cpp
void change_ref(Gradient& value) {
    value.start = 100;
}

void change_pointer(Gradient* value) {
    value->start = 200;
}
```

`change_ref(data)`는 참조 매개변수를 원본에 연결하고, `change_pointer(&data)`는 원본 주소를 포인터 매개변수에 복사합니다. 첫 호출 이후 원본의 시작값은 100, 둘째 호출 이후에는 200입니다. 두 함수 모두 원본을 수정하지만 주소를 제공하는 소스 문법이 다릅니다.

두 번째 함수의 포인터는 값으로 전달됩니다. 복사되는 것은 `Gradient` 전체가 아니라 주소입니다. 복사한 주소로 같은 원본을 찾아가므로 원본을 바꿀 수 있습니다. 이 예제의 포인터 매개변수는 유효한 원본 주소를 요구하며 null을 처리하는 분기를 제공하지 않습니다.

반면 함수 안에서 `value = &other`를 실행하는 것은 복사된 포인터의 주소 값만 바꾸는 연산입니다. 호출자 쪽 포인터 `p`까지 다른 주소로 바꾸려면 `Gradient*& value`처럼 그 포인터 객체에 참조로 연결해야 합니다. `Gradient*&`는 `Gradient*` 타입 객체에 대한 참조입니다. 원본 필드를 바꾸는 경우와 호출자의 주소 변수를 바꾸는 경우에 대상이 달라지는 것입니다.

배열의 시작 주소와 개수는 C++20 표준 타입 `std::span<int>`로 묶을 수도 있습니다. span은 외부 원소에 접근할 주소와 길이를 제공하고 원소 저장 공간을 소유하지 않는 범위 타입입니다. `void fill(std::span<int> values)`처럼 값으로 받아도 원소 배열 전체를 복사하지 않습니다. 복사한 접근 정보를 통해 원본 원소를 수정할 수 있습니다. `const std::span<int>`는 그 접근 정보 객체를 const로 만들고, `std::span<const int>`는 원소를 읽기 전용으로 다룹니다. 4편의 포인터와 외부 대상 구분을 적용한 사례입니다. [표준 초안: span](https://eel.is/c++draft/span.overview)

**호출 규약은 값을 어느 위치로 전달할지 정합니다.**

호출 규약(calling convention)은 인수와 결과를 어떤 레지스터나 메모리 위치에 둘지 호출자와 함수가 공유하는 약속입니다. 이 시리즈의 x86-64 Linux 환경에서는 첫 번째 정수·포인터 인수에 `rdi` 계열 레지스터를 사용합니다. 32비트 정수는 그 하위 부분인 `edi`, 64비트 주소는 `rdi`로 봅니다.

1편의 값 인수 `int`는 숫자 자체를 레지스터로 받았습니다. 3편의 `int&`는 원본의 주소를 같은 계열 레지스터로 받았습니다. 따라서 참조로 받는다고 매개변수 전용 메모리를 반드시 확보하지는 않습니다. 원본 정수를 읽거나 쓰는 메모리 접근과, 매개변수의 주소 값을 보관하는 공간은 별도로 생각해야 합니다.

작은 구조체도 레지스터로 전달될 수 있습니다. 현재의 두 정수 `Gradient`는 이 환경에서 값 매개변수로 전달할 때 두 필드의 내용을 합친 8바이트를 레지스터로 받습니다. 이것은 두 필드 값을 제공하는 구현이지 원본 주소를 제공하는 구현이 아닙니다. 큰 객체나 사용자 정의 생성·소멸 동작이 있는 타입은 다른 호출 방식이 사용될 수 있습니다. 레지스터 개수와 전달 방식은 타입과 플랫폼의 ABI, 즉 바이너리 수준 인터페이스 규칙에 달려 있습니다.

**읽기만 하는 입력은 const 경로로 제한할 수 있습니다.**

`int read_start(const Gradient& value) { return value.start; }`는 원본을 읽되 그 경로로 수정하지 못하게 합니다. 현재 `Gradient`는 작고 저렴하게 전달될 수 있으므로 반드시 참조로 받아야 하는 타입은 아닙니다.

비야네 스트롭스트룹과 허브 서터가 편집하는 공개 설계 지침인 C++ Core Guidelines에서는 작은 입력은 값으로, 그 밖의 읽기 입력은 const 참조로, 수정할 필수 대상은 참조로 받도록 권장하고 있습니다. 좋은 설계의 출발점이며 모든 프로젝트의 강제 규칙은 아닙니다. [Core Guidelines F.16/F.17](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rf-in)

함수가 원본을 처리한 뒤 호출자에게 무엇을 제공하는지도 별도로 정할 수 있습니다. 같은 참조 매개변수를 읽더라도 사본을 반환할 수 있고 원본에 대한 참조를 반환할 수 있습니다. 다음 편에서는 함수의 반환 타입과 호출자의 선언을 이어서 읽습니다.
