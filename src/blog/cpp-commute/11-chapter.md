앞 편에서는 기존 객체로 새 객체를 초기화할 때 복사·이동 생성자가 선택되는 과정을 보았습니다. 그런데 함수가 새 결과를 반환할 때는 별도의 중간 객체를 만들지 않아도 됩니다. 여기서는 언어가 정한 직접 생성과 선택적으로 허용한 복사 생략을 나누어 보겠습니다.

```cpp
Packet direct() {
    return Packet{7};
}
Packet result = direct();
```

`Packet`은 정수 하나를 인수로 받아 만들어지는 예제 타입입니다. 이 생성과 복사·이동 생성을 구별하고, 복사·이동 생성자에서는 각 횟수를 기록합니다. `Packet{7}`과 `direct()`는 prvalue이며 결과 객체를 초기화합니다.

**C++17 이후의 이 형태는 목적지에 직접 생성합니다.**

같은 타입의 prvalue로 객체를 초기화하는 지금 경우에는 중간 Packet을 만들었다가 차례로 이동시키는 과정이 필요하지 않습니다. 함수의 결과 객체가 호출자의 `result`이며 복사·이동 생성 횟수는 0입니다. C++20에서 `-O0`으로 컴파일해도 이 동작은 유지됩니다. [표준 초안: 객체 초기화](https://eel.is/c++draft/dcl.init.general)

이 경우를 흔히 보장된 복사 생략이라고 부르지만, 언어 모델을 읽을 때는 처음부터 중간 객체를 요구하지 않는 직접 생성으로 이해하는 것이 더 정확합니다. 복사·이동 생성자를 삭제한 타입으로도 이 형태의 반환과 초기화가 가능했습니다. 필요한 소멸자는 사용 가능해야 합니다.

**이름 있는 지역 객체를 반환하는 NRVO는 선택 사항입니다.**

```cpp
Packet named() {
    Packet local{7};
    return local;
}
```

여기서는 이름 `local`을 반환합니다. 조건을 만족하면 컴파일러가 `local`을 함수 결과의 저장 위치에 처음부터 만들 수 있습니다. 이를 NRVO(named return value optimization)라고 부릅니다. 소스의 지역 객체와 결과 객체를 하나로 취급하는 선택적 생략입니다. 반환 타입과 같은 클래스 타입의 비휘발성 지역 객체여야 하는 등 조건이 있으며 함수 매개변수에는 이 NRVO 규칙이 적용되지 않습니다. [표준 초안: 복사·이동 생략](https://eel.is/c++draft/class.copy.elision)

이번 Clang 18.1.3과 GCC 13.3에서는 `-O0`, `-O2` 모두 이 예제의 복사·이동이 0회였습니다. `-fno-elide-constructors`를 추가하자 NRVO를 하지 않아 이동 1회가 관찰됐습니다. 앞의 `direct()`는 같은 옵션에서도 계속 0회였습니다. 최적화 수준 하나로 모든 반환 복사를 설명할 수 없는 이유입니다.

C++20에서는 이런 지역 객체를 반환할 때, 생략되지 않으면 이동 생성자를 선택할 수 있도록 시도하는 특별한 규칙이 있습니다. 이름을 일반 표현식으로 쓰면 lvalue라는 앞의 설명을 유지하면서도, 이 반환 문맥의 규칙을 함께 적용합니다. C++23에서는 관련 표현식 규칙이 바뀌었으며 이 글의 검증 모드는 C++20입니다.

따라서 `return std::move(local);`로 바꾸는 것이 자동 개선은 아닙니다. 반환식이 지역 이름 자체인 NRVO 형태를 벗어나, 이 예제에서는 원래 생략할 수 있던 이동을 수행하게 됩니다. 두 컴파일러도 이런 코드에 불필요한 이동 변환 경고를 냈습니다.

**복사·이동 생성 횟수는 일반 최적화로 마음대로 바꾸지 못합니다.**

첨부 `Packet`은 복사 생성자에서 `copies`, 이동 생성자에서 `moves`를 증가시킵니다. `Packet(const Packet& other)`는 복사 생성자이고 `Packet(Packet&& other)`는 이동 생성자입니다. 생성자 뒤의 `: value(other.value)`는 멤버 초기화 목록으로, 새 객체의 필드를 원본 값으로 초기화합니다.

이 카운터처럼 관찰 가능한 효과가 있으면 일반 as-if 최적화는 그 결과를 보존해야 합니다. 다만 표준이 허용한 NRVO는 생성·소멸자의 부수 효과가 있더라도 생략할 수 있는 별도 규칙입니다. 생성자를 기록하는 로그 실험이 이 예외의 영향을 받을 수 있습니다.

```cpp
Packet passthrough(Packet value) {
    return value;
}
Packet a{7};
Packet b = passthrough(a);
```

함수에 들어갈 때 lvalue `a`로 매개변수를 복사합니다. 매개변수는 NRVO 대상이 아니므로 결과로 반환할 때 이동을 관찰할 수 있습니다. 이번 실험에서는 기본 옵션과 생략 제한 옵션 모두 복사 1회·이동 1회였습니다. 기계어의 함수 호출이 인라인되더라도 이 예제의 관찰 가능한 카운터 결과는 유지됩니다.

**큰 결과를 값으로 반환해도 숨은 목적지 주소를 사용할 수 있습니다.**

```cpp
struct Big { int values[8]; };
Big make_big() {
    return Big{{1, 2, 3, 4, 5, 6, 7, 8}};
}
```

이 환경의 ABI는 이 32바이트 결과에 호출자가 제공한 저장 공간을 사용합니다. 함수는 숨은 인수 `rdi`로 목적지 주소를 받고 그곳에 결과를 채웁니다. 실제 기계어에서는 16바이트를 다루는 `xmm0` 레지스터로 상수를 읽어 목적지 두 곳에 기록했습니다. [실제 어셈블리](/downloads/cpp-commute/artifacts/optimized.s)의 `make_big` 부분에서 확인할 수 있습니다.

숨은 주소를 전달했다고 C++ 함수의 반환 타입이 참조가 된 것은 아닙니다. 호출자가 소유할 새 결과를 초기화하는 구현입니다. 반대로 참조 반환은 기존 원본의 주소를 제공하며 그 원본의 수명에 의존합니다. 기계어에서 주소가 보인다는 사실만으로 두 의미를 같게 판단하지 않습니다.

또한 복사 생성 0회라는 말이 결과를 채우는 메모리 쓰기까지 0회라는 뜻은 아닙니다. 직접 생성한 배열에도 초기값을 기록해야 합니다. 다음 편에서는 이런 언어 수준의 생성 규칙을 유지하면서, 지역 주소 저장과 읽기 명령을 LLVM이 어떻게 줄이는지 살펴봅니다.
