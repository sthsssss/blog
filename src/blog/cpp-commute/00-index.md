C++에서 그라데이션을 복사해 편집하는 코드와, 원본에 접근해 수정하는 코드는 비슷하게 보일 수 있습니다. 여기에 `const`와 함수 반환이 붙으면 원본이 몇 개인지, 어느 쪽을 수정하는지부터 다시 확인해야 합니다. 기계어에서는 주소나 복사 명령까지 없어질 수 있으므로 소스 코드의 의미와 실제 구현도 함께 읽어야 합니다.

이 시리즈는 이 관계를 작은 `Gradient` 예제 하나에서 시작해 설명합니다. 먼저 객체와 주소를 구분하고, 같은 객체를 사용하는 포인터와 참조를 살펴봅니다. 그 위에 수정 권한과 함수 호출을 놓은 뒤, 반환 결과를 연결하는 규칙이 왜 필요한지에 따라 값 범주를 도입합니다. 복사·이동과 최적화는 그다음에 읽습니다.

**같은 코드에서 한 조건씩 바꿉니다.**

기본 타입은 `struct Gradient { int start; int end; };`입니다. 별도 설명이 없으면 각 코드 블록은 해당 문단의 독립 예제이며, 앞 블록에서 수정한 값을 이어받지 않습니다. 코드의 `//` 뒤에는 예상 결과나 제한 사항을 적었습니다. 필요한 헤더와 `main`을 갖춘 전체 소스는 각 편 끝에 연결되어 있습니다.

본문의 “새 객체를 복사한다”는 설명은 C++가 제공하는 동작을 뜻합니다. 이어지는 어셈블리는 지정한 컴파일러에서 관찰한 구현입니다. 이 두 설명을 혼합해 “소스에 변수가 있으니 반드시 스택 공간이 있다”거나 “복사 생성이니 반드시 memcpy를 호출한다”고 해석하지 않습니다. 두 설명의 관계 자체가 이 시리즈의 주제입니다.

어셈블리는 **Clang 18.1.3, x86-64 Linux, C++20, `-O2`**를 기준으로 합니다. 이 환경은 System V 호출 규약을 사용합니다. Windows x64의 인수 레지스터나 CUDA 커널의 호출 방식에 이 레지스터 이름을 그대로 적용하지 않습니다. CPU 명령의 표기는 Intel 문법입니다. 레지스터와 명령의 뜻은 1편과 2편에서 필요한 만큼 소개합니다.

**이 글에서 인용하는 자료**

Microsoft의 개발 문서 사이트인 **Microsoft Learn**은 C++ 기능과 사용 예제를 확인할 때 참고합니다. 언어 규칙의 더 정확한 조건은 **C++ 표준 작업 초안**에서 확인합니다. 링크에 사용하는 `eel.is`는 초안을 웹에서 읽도록 제공하는 사이트이며 ISO에서 발행한 표준 정본은 아닙니다. 갱신되는 초안 중 이 시리즈가 사용하는 기능은 C++20 범위로 한정했습니다. [Microsoft C++ 문서](https://learn.microsoft.com/en-us/cpp/), [표준 초안 안내](https://eel.is/c++draft/)

**C++ Core Guidelines**는 비야네 스트롭스트룹과 허브 서터가 편집하는 공개 설계 지침입니다. 문법의 허용 여부와 코드 설계의 권고를 구별하기 위해 인용합니다. **LLVM**은 Clang이 사용하는 최적화·코드 생성 기반이며, LLVM 문서는 실제 변환의 역할을 확인하는 자료입니다. GPU 부분은 **NVIDIA의 CUDA 문서**와 실제 장치 실행을 근거로 설명합니다.

본문에는 조합표를 두지 않았습니다. 같은 원본을 복사하거나 참조하는 과정과, 그 결과를 읽고 수정하는 과정을 순서대로 서술합니다. 전체 예제의 출력과 컴파일 오류, IR·어셈블리 원문은 [90 - 예제와 어셈블리 검증 기록](/posts/c-출근길-부록-예제와-어셈블리-검증/)에 연결되어 있습니다.
