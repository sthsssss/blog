전역 메모리 액세스 병합(coalescing)은 워프의 스레드들이 요청한 주소를 메모리 시스템이 필요한 전송 단위로 묶어 처리하는 동작입니다. 스레드 하나의 접근만 보면 효율적으로 보이는 코드도, 같은 워프의 다른 스레드가 어떤 주소에 접근하는지에 따라 전체 요청 수가 달라질 수 있습니다.

이 문서에서는 연속된 배열 기록을 기준으로 접근 배치의 영향을 설명합니다. 이후 선형 계층에서 스레드별 작업을 배정할 때 같은 기준을 적용합니다.

## 연속된 원소에 기록

패턴 커널에서 인덱스가 연속된 스레드는 연속된 출력 원소에 기록합니다.

```cpp
output[index] = 3 * index + 7;
```

각 원소가 4바이트이고 워프의 스레드 32개가 모두 참여하면 전체 접근 범위는 128바이트입니다. 첫 스레드가 접근하는 주소를 `A`라고 하면 다른 스레드는 `A + 4`, `A + 8`과 같은 주소를 사용합니다.

```text
레인       0      1      2      3         31
주소       A     A+4    A+8   A+12       A+124
```

compute capability 6.0 이상에서 이러한 접근을 설명할 때에는 필요한 32바이트 구간 수를 기준으로 볼 수 있습니다. 시작 주소가 적절하게 정렬되어 있으면 연속 128바이트는 네 구간에 들어갑니다.

NVIDIA의 [전역 메모리 액세스 병합 지침](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#coalesced-access-to-global-memory)은 이 구간 수와 주소 정렬의 관계를 설명합니다. GPU 세대에 따라 규칙의 세부 사항이 달랐으므로, 오래된 GPU용 접근 규칙을 현재 장치에 그대로 적용하지 않아야 합니다.

## 시작 위치가 달라지는 경우

동일한 워프가 원소를 하나씩 뒤로 이동하여 접근한다고 가정합니다. 접근 범위는 여전히 연속 128바이트이지만, 시작 주소가 32바이트 경계에서 4바이트 어긋나면 다섯 구간에 걸칠 수 있습니다.

데이터의 양은 같아도 요청해야 하는 구간은 늘어납니다. 따라서 배열이 연속이라는 사실뿐 아니라 첫 주소가 어떤 경계에 놓이는지도 중요합니다.

다만 구간 수가 늘었다고 실제 DRAM에서 읽는 양이 항상 같은 비율로 증가하는 것은 아닙니다. 앞선 워프가 읽은 구간이 캐시에 있을 수 있습니다. 메모리 요청, 캐시 적중 및 외부 메모리 트래픽은 구분해서 측정해야 합니다.

## 스레드 사이의 간격이 커지는 경우

이번에는 각 스레드가 `output[index * stride]`에 접근한다고 가정합니다. `stride`가 1이면 연속 접근입니다. 간격이 커지면 같은 워프가 넓게 떨어진 여러 구간을 요청하게 됩니다.

이때 각 스레드는 여전히 원소 하나에만 접근합니다. 비효율은 한 스레드의 명령 수가 아니라, 워프 전체가 사용한 데이터에 비해 많은 메모리 구간을 요청한다는 데 있습니다.

배열을 읽거나 쓰는 순서는 프로그램의 정확성을 만족하는 한 바꿀 수 있습니다. 그러나 스레드 순서를 바꾸었다고 메모리 배치가 자동으로 좋아지는 것은 아닙니다. 같은 명령에서 같은 워프가 요청하는 주소를 직접 확인해야 합니다.

## 선형 계층의 가중치 접근

행 우선으로 저장한 가중치에서 출력 번호를 `o`, 입력 번호를 `i`라고 하면 한 원소의 위치는 다음과 같습니다.

```cpp
weights[o * inputCount + i]
```

스레드 하나가 출력 하나를 맡으면 그 스레드는 입력 반복문을 돌며 가중치의 한 행을 연속해서 읽습니다. CPU 코드 관점에서는 자연스러운 접근입니다.

하지만 같은 워프의 인접 스레드는 서로 다른 `o`를 갖습니다. 입력 반복문의 같은 단계에서는 각 스레드가 `inputCount`개 원소만큼 떨어진 주소를 읽습니다. 입력 수가 784라면 인접 스레드 사이의 주소 차이는 3,136바이트입니다.

이 예에서는 “각 스레드가 연속해서 읽는다”와 “한 워프가 한 번에 연속 주소를 읽는다”가 다릅니다. GPU의 병합을 판단할 때 필요한 것은 후자입니다.

여러 스레드가 한 행을 나누어 읽도록 작업 분배를 바꾸면 연속 접근을 만들 수 있습니다. 대신 부분 합을 결합하는 과정이 필요합니다. 가중치를 전치하여 저장하는 방법도 있지만 변환 비용과 다른 연산의 배치를 함께 고려해야 합니다.

이처럼 메모리 최적화는 저장 형식만의 문제가 아닙니다. 스레드의 담당 작업과 결과 결합 방식이 함께 바뀔 수 있습니다. 다음 문서에서는 여러 스레드가 부분 결과를 공유 메모리에 저장하고 합치는 기본 동작을 설명합니다.
